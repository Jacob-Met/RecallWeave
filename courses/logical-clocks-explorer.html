    04 · Compare two recorded events

    A label is not a causal path

    Only events recorded in the selected snapshot are available. A directed path establishes happens-before. Complete componentwise vector order agrees with that path relation in this fixed model.

    Choose the left and right event

    Record an event to start comparing. Record A3 and C3 to inspect a concurrent pair with unequal Lamport labels; A3 and B2 expose a scalar tie.

    Lamport labels

    One-way implication: a happens-before path implies a smaller scalar label. A smaller scalar label alone does not establish a path.

      Read the assumptions

      A complete model, not a clock service

      This is the guide’s fixed ten-event graph with exactly the program-order and message edges shown above. All events and messages are known. There are no hidden communications, reused process identities or clock resets within a presentation.

      “Concurrent” means no happens-before path in either direction in this complete model. Missing observations in a real system would require an uncertainty assessment; this explorer does not infer concurrency from an incomplete log.

      Clock rules and useful checks
      • Local and send events increment the scalar and their own vector component once. A send then attaches those recorded clocks to its message.
      • A receive takes the maximum local/message scalar and each component maximum, then increments its own scalar and vector component once.
      • At A4, inspect how A’s newer local component survives the merge with the incoming message.
      • Finish one presentation, note the event table, then reset and choose another legal order. Each fixed event keeps its clock labels.
      • Reset starts a new presentation. It does not introduce a reset event into the graph.

      No wall-clock accuracy, synchronization, authentication, conflict-resolution policy or learning-effect claim is made. Read the original guide · sibling file for the mathematical scope and references.
