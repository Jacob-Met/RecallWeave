# Stable sorting: source and receiving

The original twelve-question course and offline record explorer are ready for integration in [RecallWeave PR71](https://github.com/Jacob-Met/RecallWeave/pull/71). The source passes native and independent checks; actual browser receiving covers both explorer formats and the downloaded lesson's current learner flow. This packet keeps those distinct results and their earlier negatives tied to exact source.

## What a learner can do

Open `stable-sorting.html` directly from disk, or serve `stable-sorting/index.html` with the existing static-server workflow. Enter 2–8 labeled records with integer keys from −99 to 99. Numbered input identities stay attached to whole records even when labels repeat.

Start a comparison explicitly, then move through insertion and selection independently with Back, Next and Show final. The first worked example produces C/A/B under insertion and C/B/A under selection: both final key lists are sorted, but selection's distant exchange reverses the two key-2 identities.

Each panel shows the declared key-comparison and distinct-position exchange counts. It separately states the recipe's general stability guarantee and the final tie order observed for this input. An input with no repeated keys is labeled as having no tied order to compare. Counts are not elapsed-time measurements.

Changing any draft field, row membership or example retires the prior comparison and disables its download until a new valid Start. **Download complete comparison (.json)** saves both full traces even while the learner is viewing an early state. **Download lesson (.json)** saves the exact checked-in course independently of that draft. The comparison file is an inspection artifact, with no restore/import promise.
