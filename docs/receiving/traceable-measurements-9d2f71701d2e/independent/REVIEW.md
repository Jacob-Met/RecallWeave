## UI source relationship and limits

The unchanged app.mjs renders display positions from orderOptions while storing canonical option indices in data-choice and data-practice-choice. Its handlers pass those canonical indices to first-answer or practice actions. Its lesson restoration callback rehydrates first answers, model estimates and stored option orders, then renders the saved question or feedback state. Its completed-trace restoration callback uses the native review/practice snapshots. The exported custom-course application prompt is the same generic prompt supplied by this receiver:

“Choose one connection from this deck and explain how it relates to another idea in your own words.”

These are read-only source observations recorded in SOURCE_WIRING.json. This receiver executes the underlying exported modules and actual file handoffs; it does not claim to have driven those DOM handlers or a browser download chooser. The author is responsible for the separately scoped actual browser/UI receiving. No browser profile, simulator, model, catalog or UI implementation was changed here.

Reflections are deliberately written after completed-trace restore. Native trace archives do not promise to persist free-text reflections. Study notes are a separate readable text download, and their footer explicitly states that they do not restore the browser session after a refresh. The receiver checks this distinction instead of claiming that a text note is an importable archive.

The deterministic answer schedule is an integration fixture. Six first-answer successes and five retry successes describe only that script. No classroom outcome, clinical/reference validity, force calibration, measurement accuracy beyond the author's declared source analysis, or assessment quality is inferred.
