1. Choose the text and pattern

Positions start at 0 and count Unicode code points. Matching is literal and case-sensitive: no normalization, regular expressions or grapheme grouping. Text may be empty; a pattern must contain 1–16 code points. Text is limited to 64.

Choose inputs, then build the complete traces.

2. Inspect the accepted calculation


        

        
Each panel starts at its initial state. Previous, Next and the step selector inspect an already complete trace; they do not run more comparisons. A comparison is one equality test. Recording a result, moving a cursor and applying a fallback add zero comparisons.

        
        
Editing either input retires this result until you build again. The download includes every step in all three traces, not just the current panels.

      

      

        
Naive search
Try every feasible full-pattern start, including overlaps. Compare left to right and stop an alignment on its first mismatch.

        
Prefix preparation
pi[i] is the longest proper prefix that is also a suffix of the pattern through i. A proper border is shorter than that whole prefix. Uncomputed entries are —.

        
KMP search
i is the next text position; q is the matched-prefix length. On a mismatch with q > 0, retain q = pi[q − 1] and compare the same text token again. After a full match, use the same border rule to preserve overlaps.

What these numbers mean

      
This is a prefix-function KMP variant. Preparing a pattern and searching a text has a linear combined bound, but that does not promise fewer comparisons on every small example. Prefix preparation and text search are shown separately. Counts are not elapsed-time measurements. Full teaching snapshots use more space than the underlying algorithm's working state.
