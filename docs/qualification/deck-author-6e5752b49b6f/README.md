# RecallWeave local deck authoring

This packet qualifies the separate author page for [issue 10](https://github.com/Jacob-Met/RecallWeave/issues/10). A learner or teacher can write a course through labeled controls, check its concepts and answer key, download its JSON file, and reopen that file for further editing. The modular page is `author/index.html`; `author.html` is the self-contained version for direct offline use.

## Behavior and design

Editable concepts, questions and choices have stable private identities. Renaming a concept updates its question and prerequisite references when the deck is compiled. Reordering choices or deleting a choice before the selected answer preserves the correct choice. Deleting the selected correct choice requires a new explicit answer selection. Removing a used concept is refused; the author can change its uses first. A removed question can be restored without undoing later changes to other text.

Checking creates an immutable deck snapshot using the existing validator. The actual pretty-printed JSON is then passed through `parseDeck`, so byte limits apply to exactly what the browser downloads. This matters because `serializeDeck` validates the fields but does not enforce the final UTF-8 file size. Cycles, uncovered concepts, duplicated choice text, missing answers and oversized files remain editable after refusal. The error action focuses an appropriate field or question selector.

Every content edit invalidates the previous preview and disables download until a fresh check. Preview text is placed through text nodes. Quotes, newlines, Unicode and HTML-like text remain data. File download uses the current checked bytes. Drafts stay in this page's memory; download and reopen are the explicit save workflow.

The separate reopen controller previews a local file before replacing the draft. Cancel, refusal and unreadable files preserve the existing editor and its checked snapshot. A newer file choice retires older asynchronous reads. Replacing a deck converts the admitted immutable deck into new editable state, clears the old undo/check state and focuses the title.

## Final copy delta and integration limits

The original browser-received author copy directed users to the learner's deck picker. That picker is not yet in the current-main learner app. The final template therefore describes saving, sharing and reopening a deck, and the README links the separate importer work in issue 7. Root review then found the same mismatch in the dynamic download-success status. That one string now says “Deck download started. Keep the JSON file to share or reopen it here.” The source compatibility receiver checks exactly two static text replacements and one status-string replacement against the independent peer's archived source; no DOM element, control flow, style, validator or loader changed. A focused actual-download check on the corrected standalone file passed at 390 px with network offline, exact downloaded bytes and the new status text; final builder parity also passed. The original R1 source/evidence records and archive remain preserved.

The importer browser result is intentionally bounded to its archived owner snapshot. That older app/builder omits now-merged notes and answer-order integration. It proves that the real downloaded file can be admitted and learned through the current importer contract; it does not claim those learner features have been composed with that importer. No in-progress importer app, builder or learner stylesheet replaced current main. Source coordination and this boundary were recorded in issue 7 comment 6057738158 before final packaging.

## Reproduce

The project remains dependency-free at runtime. The default test command now requires Node 20+ and Python 3 (`python3` on PATH): the local-file tests use Node's global File and the standalone-parity test calls Python. The README prerequisites were corrected after independent receiving; no Node 18 execution is claimed. CI already uses Node 20. Run the existing suite and verify the standalone author file from the repository root:

```sh
node --test tests/*.test.mjs
python3 tools/make_author.py --check
python3 docs/qualification/deck-author-6e5752b49b6f/receive-source-composition.py
```

Open `author.html` directly for the offline editor, or serve the repository and open `author/index.html`. Browser harnesses in this packet accept an explicit source root, output directory, existing Chromium executable and installed Playwright path. `receive-author-browser.mjs` exercises the editor; `receive-imported-author-deck.mjs` exercises the archived `importer-contract-source` with the actual downloaded JSON. The independent peer archive contains its separate browser harness, unchanged input files, actual reexports, screenshots, both receiver revisions and full manifest. No live provider, existing browser session, deployment or account operation was used.
